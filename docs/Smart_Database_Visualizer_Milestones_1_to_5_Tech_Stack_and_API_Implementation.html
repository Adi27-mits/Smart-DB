PART 1: Technology Stack (Milestones 1–5) & Mechanical Operation

The Smart Database Visualizer is an enterprise schema visualizer, structural analytics platform, and health inspection system. It extracts relational metadata from live MySQL catalogs at runtime with zero hardcoded definitions.

Milestone 1 — Backend Foundation & Connection Engine Core Infrastructure
Node.js (v24 LTS) Express (4.19.2) mysql2/promise (3.10.1) Zod (3.23.8) Helmet (7.1.0) CORS (2.8.5) express-rate-limit (7.3.1) dotenv (16.4.5)

How the Technology Works Mechanically:

  • Connection Pooling (mysql2/promise): In backend/src/config/database.js, connections are managed through createPool({ waitForConnections: true, connectionLimit: 10, queueLimit: 0 }). Rather than creating and tearing down TCP handshakes on every HTTP hit, sockets are recycled, dropping query latency from ~50ms to <2ms.
  • Pre-Flight Validation (Zod): In backend/src/validators/databaseValidator.js, connectSchema.safeParse() validates that ports are integers (1024–65535) and enforces a strict regex allowlist on database names (/^[a-zA-Z0-9_]+$/), completely neutralizing SQL injection at the network entry point.
  • Security Middleware: helmet() sets 11 HTTP security headers preventing MIME-sniffing and clickjacking; cors() restricts requests to the configured frontend origin; express-rate-limit limits each IP to 500 requests per 15 minutes.
Milestone 2 — Schema Introspection & Normalization Engine Catalog Discovery
MySQL INFORMATION_SCHEMA Parameterized SQL Queries REST Controllers TypeScript Schema Model

How the Technology Works Mechanically:

  • Zero-Config Catalog Queries: In backend/src/services/schemaService.js, the server dynamically queries MySQL's internal ANSI metadata catalog using parameterized placeholders (?):
    • INFORMATION_SCHEMA.TABLES: Discovers base tables where TABLE_SCHEMA = ? AND TABLE_TYPE = 'BASE TABLE'.
    • INFORMATION_SCHEMA.COLUMNS: Reads column names, data types, IS_NULLABLE, defaults, and auto-increment.
    • INFORMATION_SCHEMA.KEY_COLUMN_USAGE: Maps foreign key pairs (source child column → target referenced column).
    • INFORMATION_SCHEMA.TABLE_CONSTRAINTS: Resolves Primary Keys, Foreign Keys, and Unique constraints.
  • Normalization: schemaService.getOverview() packages these raw catalog rows into a normalized JSON payload matching the TypeScript DatabaseSchema interface (containing tables[] and relationships[] with cardinality: 'N:1').
Milestone 3 — Interactive Visual Canvas & Hierarchical Auto-Layout Visualization
Next.js 16 (App Router) React 19 TypeScript 5.7 @xyflow/react (React Flow 12.12) dagre (0.8.5) Tailwind CSS 4 Lucide React

How the Technology Works Mechanically:

  • Custom Canvas Nodes (TableNode.tsx): React Flow renders custom table cards with colored badges: PK (Primary Key), FK (Foreign Key), UQ (Unique), and IDX (Indexed).
  • Cubic Bezier Edges (RelationshipEdge.tsx): Computes dynamic SVG bezier paths between child and parent handles. Confirmed database FKs render as solid blue lines; cardinality chips (N:1) are attached at the midpoint.
  • Size-Aware Dagre Engine (dagreLayout.ts): Converts tables into an in-memory directed graph. Measures exact node heights based on column count ($\text{Height} = 42 + N \times 28\text{px}$) and computes non-overlapping $(x, y)$ coordinates in Left-to-Right (LR) or Top-to-Bottom (TB) directions.
Milestone 4 — Rule-Based Health Engine & Dependency DAG Health & Diagnostics
Structural Graph Theory (DAG) STATISTICS Introspection Rule Evaluators (R001–R005) Health Scoring Formula

How the Technology Works Mechanically:

  • Rule Engine (ruleEngine.js): Executes 5 independent structural evaluators:
    • R001 (HIGH): Detects tables lacking primary keys (1NF violation).
    • R002 (MEDIUM): Evaluates in-degree and out-degree; flags isolated tables with 0 relationships and provides review guidance.
    • R003 (MEDIUM): Heuristically matches unlinked columns with _id suffixes against target primary keys. Rendered as dashed amber lines without mutating the declared schema.
    • R004 (LOW): Cross-references relationship columns with INFORMATION_SCHEMA.STATISTICS to flag unindexed join columns.
    • R005 (HIGH): Builds a dependency Directed Acyclic Graph (DAG) to detect circular dependencies and compute table depths.
  • Health Scoring Math: $\text{Score} = \max\Big(0, \, 100 - (15 \times \text{High} + 8 \times \text{Medium} + 3 \times \text{Low})\Big)$.
Milestone 5 — Table Explorer, Query Console, CRUD & Stabilization Production Integration
5-Tab Explorer Read-Only SQL AST Parser 13-Point FK Pre-Validator Base UI / Radix Parameterized CRUD

How the Technology Works Mechanically:

  • 5-Tab Table Explorer (TableDetailsPanel.tsx): Renders real catalog data across Overview, Columns, Keys & Constraints, Indexes (from STATISTICS), and Relationships with one-click navigation.
  • Read-Only Query Console (queryService.js): Tokenizes incoming SQL by stripping block/line comments; permits only SELECT, SHOW, DESCRIBE, DESC, EXPLAIN, and read-only WITH CTEs. Mutating statements return READ_ONLY_QUERY_CONSOLE. Chained semicolons return MULTIPLE_STATEMENTS_NOT_ALLOWED. MySQL errors (ER_NO_SUCH_TABLE, 42S02) are preserved via ApiError.
  • 13-Point FK Pre-Validation (schemaEditService.js): Prior to executing ALTER TABLE, validates table/column existence, data type compatibility (INT vs VARCHAR), signed/unsigned parity, target index presence, and executes a subquery to ensure zero orphan child rows exist.

2. Credential Flow & In-Memory Session Architecture (Step-by-Step)

  1. User Input on Connect Screen: In frontend/components/connect-screen.tsx, the user specifies credentials (host, port, username, password, database).
  2. Dispatched to API Helper: The component calls connectToDatabase(payload) in frontend/lib/schema-api.ts, issuing POST /api/database/connect.
  3. Zod Input Validation: Intercepted by backend/src/validators/databaseValidator.js to verify data types, port ranges, and identifier safety.
  4. Session Pool Creation (app.locals.dbPool): In backend/src/controllers/databaseController.js: 
    if (req.app.locals.dbPool) {
  await req.app.locals.dbPool.end().catch(() => {})
}
// Store connection pool in Node.js server process memory
req.app.locals.dbPool = createSessionPool(config)
req.app.locals.dbName = config.database
req.app.locals.dbType = 'MySQL'
  5. Credential Sanitization in Response: The backend confirms connection with: 
    return res.json({
  success: true,
  message: 'Database connected successfully',
  data: {
    host: config.host,
    port: config.port,
    database: config.database,
    user: config.user,
    // PASSWORD INTENTIONALLY OMITTED
  }
})
    The password stays in server RAM only and is never returned to the client browser or written to server logs.
  6. Zero-Credential Access for Subsequent APIs: Downstream controllers (e.g. schemaController.js, queryController.js, dataController.js) read req.app.locals.dbPool directly from memory. The client does not need to pass an API key or password on every query.
  7. Clean Disconnect: Calling POST /api/database/disconnect closes all open sockets via pool.end() and nullifies req.app.locals.dbPool.
