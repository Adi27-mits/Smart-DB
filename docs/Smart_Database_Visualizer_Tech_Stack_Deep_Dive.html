1. Executive Technical Summary

Smart Database Visualizer is a high-performance web platform that dynamically introspects relational MySQL databases, extracts their relational metadata via standard INFORMATION_SCHEMA catalogs with zero hardcoding, and renders an interactive, graph-theoretically arranged Entity-Relationship (ER) diagram in the browser.

The platform pairs an asynchronous Next.js 16 (React 19) frontend with a secured Node.js + Express backend. It provides automated layout (Dagre), complete five-tab schema exploration, AST-validated read-only SQL querying, heuristic database health analysis (rules R001–R005), and interactive CRUD operations.

5. Database Layer & Catalog Introspection Engine

The visualizer does not rely on ORM models or static metadata files. It queries the MySQL INFORMATION_SCHEMA catalog in real time through parameter-bound queries:

1. Table Discovery Query

Discovers all user-created base tables in the active schema:

SELECT TABLE_NAME AS name
FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_SCHEMA = ?
  AND TABLE_TYPE = 'BASE TABLE'
ORDER BY TABLE_NAME;

2. Column Details Query

Fetches data types, nullability, defaults, and auto-increment flags:

SELECT COLUMN_NAME, DATA_TYPE,
       IS_NULLABLE, COLUMN_DEFAULT,
       COLUMN_KEY, EXTRA, COLUMN_TYPE
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = ?
  AND TABLE_NAME = ?;

3. Foreign Key Relationship Query

Resolves referential integrity links between tables:

SELECT CONSTRAINT_NAME AS constraintName,
       TABLE_NAME AS sourceTable,
       COLUMN_NAME AS sourceColumn,
       REFERENCED_TABLE_NAME AS targetTable,
       REFERENCED_COLUMN_NAME AS targetColumn
FROM INFORMATION_SCHEMA.KEY_COLUMN_USAGE
WHERE TABLE_SCHEMA = ?
  AND REFERENCED_TABLE_NAME IS NOT NULL;

4. Index Metadata Query

Queries secondary, unique, and composite indexes:

SELECT INDEX_NAME AS indexName,
       COLUMN_NAME AS columnName,
       NON_UNIQUE AS nonUnique,
       SEQ_IN_INDEX AS seqInIndex,
       INDEX_TYPE AS indexType
FROM INFORMATION_SCHEMA.STATISTICS
WHERE TABLE_SCHEMA = ?
  AND TABLE_NAME = ?;

6. Core Feature Subsystems Deep-Dive

6.1 React Flow Visualization & Layout Engine

  • Custom Table Nodes (TableNode.tsx): Render table headers, primary key badges (PK), unique badges (UQ), index markers (IDX), data types, and nullable flags.
  • Custom Bezier Edges (RelationshipEdge.tsx): Verified database foreign keys render as solid blue lines. Heuristic recommendations (R003) render as dashed amber lines and are strictly isolated from the declared schema graph.
  • Dagre Layout Engine (dagreLayout.ts): Measures node heights dynamically based on column count ($\text{Height} = 42 + N \times 28\text{px}$) to compute collision-free, hierarchical coordinates in both Left-to-Right and Top-to-Bottom orientations.

6.2 SQL Query Console & AST Read-Only Protection

  • Single Endpoint: Frontend calls POST /api/query/execute via schema-api.ts.
  • Strict Read-Only Enforcement (queryService.js): Allows only SELECT, SHOW, DESCRIBE, DESC, EXPLAIN, and read-only WITH CTE queries. Modifying statements (INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, TRUNCATE, RENAME) are rejected with error code READ_ONLY_QUERY_CONSOLE.
  • Multiple Statements Guard: Semicolon-chained commands are parsed and rejected with MULTIPLE_STATEMENTS_NOT_ALLOWED to prevent batch injection.
  • Preserved SQLState & Error Codes: Preserves native MySQL codes (e.g. ER_NO_SUCH_TABLE) and SQL states (e.g. 42S02) cleanly to the client UI.

6.3 Health Inspection & Rule Engine

The backend analysis engine executes 5 specialized structural and relational health rules:

  • R001 — Missing Primary Key (HIGH): Detects tables lacking primary keys (1NF integrity violation).
  • R002 — Potential Orphaned Table (MEDIUM): Identifies standalone tables with zero incoming or outgoing foreign keys. Provides advisory Review Guidance without generating destructive SQL.
  • R003 — Possible Missing Foreign Key (MEDIUM): Matches naming heuristics (e.g. customer_id in unlinked tables) to suggest foreign key candidates. Rendered as non-binding dashed overlays.
  • R004 — Index Review Recommended (LOW): Detects unindexed join columns that cause full table scans.
  • R005 — Structural Dependency Analysis: Builds a dependency DAG, identifying root, leaf, and circular dependencies.

Health Scoring Formula: $$\text{Score} = \max\Big(0, \, 100 - (15 \times \text{High} + 8 \times \text{Medium} + 3 \times \text{Low})\Big)$$
